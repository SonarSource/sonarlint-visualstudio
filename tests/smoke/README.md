# SLVS-3097: installed VSIX smoke test using Roslyn's harness

This is an alternative to the custom MSTest/DTE prototype in
[PR #6854](https://github.com/SonarSource/sonarlint-visualstudio/pull/6854).
It uses Microsoft's packaged
[Visual Studio integration-test harness](https://github.com/dotnet/roslyn/tree/main/src/VisualStudio/IntegrationTest/Harness),
not a copy of Roslyn's source tree. The product solution and existing unit-test
framework remain unchanged.

## Scenario

`VsixSmokeTests.InstalledExtension_DetectsIssue_AndClearsItAfterFix` is the only
product scenario:

1. The framework installs the supplied SonarQube VSIX and its own integration
   test-service VSIX into a dedicated experimental profile, then launches VS.
2. `[IdeFact]` executes the test inside `devenv.exe` on the IDE UI thread. The test
   verifies both conditions and the expected profile suffix before proceeding.
3. Copy `Fixture/Smoke.cs.txt`, `Smoke.csproj` and `Smoke.sln` to a fresh evidence
   directory, naming the source `Smoke.cs`, and open the solution and source file.
4. Require the real Error List to contain the exact sample path, line 5 and
   `Remove the unused local variable 'smokeUnused'.` The compiler's own warning
   does not satisfy this assertion.
5. Remove that declaration through the editor, save, and require the matching
   Sonar finding to remain absent for five seconds.

`SmokeScenario.cs` contains only scenario actions, bounded asynchronous waits
and evidence collection. It does not launch/attach to/kill Visual Studio or
implement VSIX installation. The framework owns those lifecycle operations.
Polling yields the UI thread so analysis and diagnostic refresh can run. No
rule-description scenario or UI screenshot-comparison assertion is included.

## Framework and package policy

The harness is pinned to `Microsoft.VisualStudio.Extensibility.Testing.Xunit`
`5.14.0-1.26551.1` from Microsoft's public `vssdk` Azure Artifacts feed. It is a
prerelease package; upgrading requires rerunning this spike. The downloaded
package contains the integration-service VSIX, and its Microsoft author
signature was verified with `dotnet nuget verify --all`.

The scoped `nuget.config` retains required signature validation inherited from
the repository. Only the exact harness package ID maps to the additional feed;
other packages retain the Repox mapping. The configuration trusts the verified
Microsoft signing certificate and adds the xUnit owner to the existing NuGet
repository signer restriction for this project only. It does not allow
untrusted certificate roots or change the product's package configuration.
The lock file pins the complete dependency graph.

The published harness references `System.Collections.Immutable` 10.0.0.10 but
omits that dependency from its package metadata. An explicit 10.0.10 package
reference prevents an older transitive dependency from winning resolution.
Interop is referenced from the selected VS installation, matching the IDE in
which the test executes. The VSTest xUnit adapter and SDK only run the test host;
`[IdeFact]` uses the custom Roslyn test framework generated by the package targets.

This pinned harness embeds a VS 18 test-service VSIX. This PR initially targets
VS 18 only. Do not infer VS 17 coverage from old enum values or the earlier
prototype's results; a version-compatible harness package needs verifying for
an oldest/latest matrix.

## Run on Windows

Prerequisites: full VS 18 Professional, .NET SDK, .NET Framework 4.8 development
references and the 4.7.2 targeting pack used by the fixture. Use a trusted signed
VSIX from the existing product build. Do not bypass VSIX signature validation.

From a PowerShell prompt:

```powershell
cd tests/smoke
$idePath = & "${env:ProgramFiles(x86)}/Microsoft Visual Studio/Installer/vswhere.exe" -latest -products Microsoft.VisualStudio.Product.Professional -version '[18.0,19.0)' -property installationPath
$env:VSInstallDir = $idePath
$env:SMOKE_RESULTS_DIRECTORY = 'C:\temp\slvs3097-roslyn-run1\evidence'
$env:XUNIT_LOGS = 'C:\temp\slvs3097-roslyn-run1\harness'
$suffix = 'SLVS3097' + [guid]::NewGuid().ToString('N').Substring(0, 12)
dotnet restore VsixSmoke.Tests.csproj --locked-mode -p:VsTargetVersion=2022
dotnet build VsixSmoke.Tests.csproj -c Release --no-restore -p:VsTargetVersion=2022 "-p:VisualStudioInstallPath=$idePath" '-p:SmokeVsixPath=C:\artifacts\candidate.vsix' "-p:SmokeRootSuffix=$suffix"
dotnet test VsixSmoke.Tests.csproj -c Release --no-build --no-restore --settings test.runsettings --filter 'FullyQualifiedName~InstalledExtension_DetectsIssue_AndClearsItAfterFix' --logger trx --results-directory C:\temp\slvs3097-roslyn-run1 -p:VsTargetVersion=2022
```

Use a new evidence directory and compile with a new suffix for each independent
attempt. The dedicated suffix cannot be empty or `Exp`; the project validates its
format. `VsTargetVersion=2022` is the repository's existing packaging target for
the VSIX that supports VS 17/18, not the IDE version selected for this test.

Before this workflow exists on master, dispatch the existing Build workflow on
this PR's branch with all three smoke inputs:

```sh
gh workflow run build.yml --ref codex/slvs-3097-roslyn-harness \
  -f vsix-smoke-version=11.3.0.17474 \
  -f vsix-smoke-runner=<exact-VS18-DEV-label-from-image-PR-513> \
  -f vsix-smoke-repetitions=3
```

The workflow accepts only the DEV label format of image PR #513. Copy the actual
emitted label; the workflow does not guess a runner or install Visual Studio.
Image provisioning belongs to the separate image PR and its owner. The smoke
entry point skips normal product build/publish/promote steps; default builds
retain their existing behavior.

## Evidence and validation status

Each attempt retains TRX results, `result.json` (VS version, VSIX identity/hash,
profile suffix and failure phase), before/after Error List JSON, saved source and
Sonar output. The framework's failure screenshots/logs are retained under
`harness`. The artifact is `slvs3097-roslyn-vsix-smoke` with seven-day retention.

CI requires one passing result for the actual scenario plus complete evidence
matching that attempt's profile and package hash. Missing/skipped tests and
framework failures cannot produce a successful smoke result.

Windows execution was attempted on the VS 18 DEV runner. The first three
attempts failed during framework setup, before the scenario body; see the
verified result below. Existing custom-harness results do not validate this
implementation.

Local validation: the project compiles with zero warnings/errors against a
verified VS 18 interop reference and .NET Framework reference assemblies. Locked
restore succeeds with signature validation required. The first restore used
public upstream packages because this shell has no Repox token; a subsequent
locked restore using the committed configuration succeeds from that verified
cache. Clean Windows restore through Repox still needs CI validation. NuGet's
transitive advisory check reported no vulnerable packages in its current data.
Actionlint and PowerShell parsing pass; using the shared `Exp` suffix is rejected.

ran; no scenario `result.json` was produced. This is not an issue-detection
failure or a successful end-to-end result.

The retained artifact contains all three TRX reports and VSIX installation logs.
A focused follow-up captures the runner's session ID, interactive-state flag and
Explorer session IDs to establish whether the agent has an interactive desktop.
No image changes or foreground-check bypass are introduced by this diagnostic.
